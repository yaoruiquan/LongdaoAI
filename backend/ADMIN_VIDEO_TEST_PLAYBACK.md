# 管理员视频测试结果回放

## 背景

管理员账号测试可以使用所选 OpenAI API Key 账号提交一次 `POST /v1/videos`，并通过 SSE 返回上游任务 ID 和初始状态。现有流程在任务受理后结束，不会查询任务，也不提供视频预览或下载。管理员因此只能去上游控制台确认生成结果。

正式中转视频 API 的查询与内容下载需要中转 API Key 对任务的账户绑定；后台测试绕过该调用路径，不应伪造或复用普通用户的绑定。

## 目标

- 后台测试任务受理后可查询原任务状态。
- 成功任务可在账号测试弹窗内播放和下载。
- 弹窗关闭、重新打开或页面刷新后，可在同一浏览器会话恢复最近的测试任务并继续查询。
- 查询和取视频内容始终使用提交任务的上游账号凭据；凭据不得传到浏览器。
- 查询、下载不得再次创建任务，不进入中转用户计费。

## 非目标

- 不建设跨设备、跨浏览器的管理员视频任务历史库。
- 不绑定或更改普通中转 API Key 的任务权限和计费。
- 不自动重试任务提交或后台轮询上游。

## 设计

### 管理端 API

在现有管理员认证路由下增加：

- `GET /api/v1/admin/accounts/:id/video-tasks/:task_id`：使用该账户的 OpenAI API Key 查询 `GET /v1/videos/{task_id}`，返回经过字段筛选的任务状态 JSON。
- `GET /api/v1/admin/accounts/:id/video-tasks/:task_id/content`：使用同一账户代理 `GET /v1/videos/{task_id}/content`，流式转发状态码、内容类型、长度、Range/缓存相关响应头及响应体。

两个端点必须验证管理员账户 ID、OpenAI API Key 类型、视频能力、任务 ID 格式、上游 URL 和 HTTP 上游客户端。查询和内容获取均使用现存 URL allowlist、代理、TLS 指纹和账户并发设置。不得接受任意上游 URL、任意账户凭据或前端传入的 Authorization。

任务 ID 限制为 1–256 个字母、数字、下划线、连字符或点，且拒绝 `.`/`..`；这些字符作为安全路径段加入现有视频 URL 构造器。错误响应不得回显上游密钥。管理员身份由既有 `/admin` 路由中间件保障。上游 401/403 转换为 502 并保留脱敏错误说明，避免被前端误判为管理员登录过期。

状态接口返回标准管理端响应封套，`data` 仅含 `{id, status, error?}`；不向浏览器返回上游 URL、认证字段或原始响应。内容接口仅接收视频或二进制媒体，拒绝 HTML/JSON 等非视频成功响应。状态和内容响应均禁止共享缓存。

### 前端恢复

- 收到 `video_task` SSE 事件后，将 `{accountId, id, status, createdAt}` 保存到 `sessionStorage` 的版本化、按账户区分的键中。
- 测试弹窗打开且当前账户支持视频测试时读取该记录；仅当 `accountId` 一致且记录有效时恢复。
- 关闭弹窗不清除任务记录；用户切换账户时不得显示其他账户任务。成功/失败结果仍保留，用户明确发起新测试并收到新任务 ID 后替换。
- 页面显示任务状态和“刷新状态”；轮询不自动触发。生成成功后展示原生 `<video controls>` 和下载操作。
- 支持手动填写当前上游账号的已有任务 ID 并查询，供升级前未保存到浏览器的任务使用。手动查询只发 GET，成功确认任务后才替换保存的记录；无需为取回旧结果再提交付费任务。
- 使用现有 `apiClient` 附带管理员 Bearer token 请求管理端 content 端点，成功后创建 Blob URL 给原生播放器和下载链接。原生 `<video src>` 无法设置 Bearer 请求头，不能直接使用管理端地址。前端不接触供应商密钥。
- 同步在现有 CSP 增强逻辑中允许 `media-src 'self' blob:`，兼容已有部署配置；关闭、切换任务或销毁组件时取消旧请求并释放 Blob URL。
- “再次提交”仍是新的付费任务操作，任务查询按钮与提交按钮必须有清楚区分。

### 状态处理

兼容上游 `id`/`task_id` 响应及常见状态：排队、处理中、完成、失败、取消、过期。保存并显示上游错误信息时先过滤密钥和敏感头。未知状态应原样显示，不能误报完成。

服务端内容接口按上游返回流式传输，支持 `Range` 请求，避免把完整视频缓冲进服务器内存。第一版浏览器需要将视频完整下载为 Blob 后播放，适用于短视频账号测试；更大视频的边下边播可后续使用短期签名的播放凭证实现。前端仅在任务完成后获取内容和挂载播放器；加载失败时显示可重试状态与任务 ID。已载入视频刷新状态时复用 Blob，不重复下载。

## 安全与费用

- 状态查询和视频下载不创建任务，不记录媒体生成用量，也不扣用户余额。
- 创建任务的既有上游费用提示保留；不得在恢复或刷新时重新 POST 创建。
- 上游 Authorization 仅由后端从被授权账户读取。
- 任务 ID 限制为安全字符集，拒绝路径、查询串、片段或编码分隔符。
- 代理视频响应时只转发必要的媒体/缓存/Range 响应头，不透传 `Set-Cookie` 或供应商认证信息。

## 验收标准

1. 已有提交测试仍只发出一次 `POST /v1/videos` 并保存其任务 ID。
2. 后端状态端点使用相同账户凭据请求正确的上游任务路径，能处理成功、错误、无效 ID、上游不可达和超大错误正文。
3. 内容端点流式代理 MP4 响应和 Range 请求，保留合理响应头且不回显凭据。
4. 非视频账户、无密钥、视频能力关闭时拒绝查询/下载且不发上游请求。
5. 前端恢复任务后可手动刷新状态；完成时显示播放器和下载入口，未完成时不发起内容下载。
6. 账户切换不串任务；恢复或查询不会触发新的付费提交；提交按钮仍明确表示会再次创建付费任务。
7. 后端相关单元测试、前端组件测试及适用的 lint/typecheck 通过。
